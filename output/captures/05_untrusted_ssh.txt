The headscale policy does NOT include tag:untrusted in any SSH rule.
Even if the sidecar had the ssh client, this would be denied.

$ docker exec headscaletest-poc-ts-untrusted-1 timeout 5 tailscale ssh eng-admin@admin-portal.headscaletest.ts.net -- whoami
no system 'ssh' command found: exec: "ssh": executable file not found in $PATH

(no ssh client in image, but the policy itself would deny tag:untrusted at lookup time.)
